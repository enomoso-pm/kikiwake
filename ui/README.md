# Kikiwake の画面（ui/）

Kikiwake（聞き分け）の画面。React 18＋TypeScript＋Vite。
受け渡しの約束の正は `../contract/`（版8）。本物のエンジンとのつなぎ `src/api/tauri.ts` は、エンジン側（`../src-tauri/`）と組で直す。
画面の設計（UI 画面仕様書 ver1.1・動く見本）は公開していない。下の「仕様書に無くて決めたこと・仕様書と違う所」は、その仕様書と違う所の一覧。

## 状況

- 5画面（準備 → ファイル → 処理中 → 名前付け → 結果・保存）と完了の画面が、見本データでも本物のエンジンでも通しで動く
- 見た目は設計の見本と実測で突き合わせ済み（画面1〜5の主な部品の文字・余白・色・枠・列の幅・位置。見本のタイトルバーの分を引いて 1px 以内）
- 自動テスト（`npm test`）・型チェック・ビルドが通る
- 確かめた作例は下の「開発用の切替」の全部。4時間・1,468行（確認用60件）で、描く行は常に20行ほど、検索・次へ・スクロール・絞り込みは1回1〜2コマ
- アプリの中（Safari と同じ WebKit）では、`../scripts/e2e_mac.sh` が開発用のビルドだけに入る操作役で5画面を自動で通す（ボタンを押して読む。ui/ のファイルは使わない）
- 画面の言語は日本語と英語（2026-09-27）。文字は `src/i18n/` の辞書にあり、工程バーの右端で切り替えられる（下の「画面の言語」）
- 履歴と閉じたときの状態（2026-09-27。約束 版8）: ファイルの画面の「履歴」から、前に文字起こしした録音を開き直す・続きから処理する・消す。名前付けで入れかけた名前と結果の画面の手直しは変わるたびに作業フォルダへ書き、開き直すと閉じたときの画面に戻る（下の「履歴と閉じたときの状態」）

## 動かし方

```bash
npm install
npm run dev        # http://localhost:1430 （ポートは固定）
npm test           # 計算の部分の自動テスト（vitest）
npm run typecheck  # 型チェック（../contract も含む）
npm run build      # 型チェック＋ビルド。出力は ui/dist
```

ブラウザで開くと見本（`src/api/mock.ts`）で動く。右上の「開発用」から作例を切り替えられる:
画面 1〜5 へ直接／データ量（見本 2分44秒・4ラベル／多い 4時間・10ラベル・確認用60）／OS（Mac・Windows）／
準備（通常・注意あり・進めない・取得途中・取得失敗・取得済み）／ファイル（通常・非対応・前回あり）／処理（通常・途中で失敗、60倍・600倍）／
閉じる操作をまねる／名前付け（通常・注意あり、台本どおりの名前・同じ名前でまとめる・空にする、確定の失敗）／
結果（確認用1件・定番の誤認識・確認用なし・繰り返しあり）／保存（通常・同じ名前のファイルあり・失敗）。
ファイルは「ファイルを選ぶ」でも、何かのファイルを窓にドラッグしてもよい（拡張子で対応・非対応が変わる）。

見本だけの違い: 名前付けのサンプルと手がかりの「▶」は、声ではなく仮の音が鳴る（`../contract/README.md`）。
結果の画面の行の再生は、見本に録音全体が無いので無音で長さぶん進む。「Finder で表示」「アプリを閉じる」は、見本では右下や全体に「（見本）…」と出るだけ。

## エンジンとの受け渡しの細かい所

- Tauri は `npm run build` の `dist` を使い、`tauri dev` のときは開発サーバ（1430 番）を読む
- 製品のビルド（`npm run build`）には、見本・見本データ・開発用パネルは入らない。インラインの script・eval・外部の読み込みも無い
- 注意: 開発サーバ（`npm run dev`）は React の再読み込みのためにインラインの script を1つ入れる。`tauri dev` でも CSP の違反は出ていない
- 呼び方の約束:
  - `applyNames` には名前の入ったラベルだけを渡す。同じ人にまとめた名前（全角・半角の違いは同じとみなす）は、一覧で上のラベルの書き方にそろえて渡す
  - `saveOutputs` の `edits`: `names` はラベルの名前と違う行だけ（確認用の行は、確定していなくても名前があれば入れる）、`confirmed` は確定した確認用の行、`texts` は直した最後の文字。何も無ければ `edits` を付けない
  - 同じ名前のファイル（`SaveResult.existing`）が返ったら確認のダイアログを出し、「上書きする」で `overwrite: true` を付けて呼び直す
  - `revealInFileManager` には保存した最初のファイルのパスを渡す（まだ保存していなければ保存先）。`pickFolder` には今の保存先を渡す
  - `recordingSrc` は行の ▶ を押したときに呼ぶ。`audioSrc` はサンプルと確認用の手がかりの再生で呼ぶ
  - `onCloseRequested` が来たら（処理中だけ届く）「閉じる確認」を出し、「閉じる」で `closeApp()`。処理中でなければすぐ `closeApp()` を呼ぶ。
    版8: 保存していない手直しがあっても確かめない（手直しは `saveDraft` で作業フォルダに残る。版6 の `setUnsavedChanges` は無くした）
  - `saveDraft` は、処理が終わった録音の名前付け・結果・完了の画面にいる間、閉じたときの状態に関わる所が変わるたびに呼ぶ（`store/draft.ts`。書いている間にまた変わったら、書き終えてからもう一度）
  - 開き直したとき（`JobDone.draft`・`HistoryOpened.draft`）は、入れかけの名前・手直し・画面を1回の setState で戻す（途中の状態を閉じたときの状態として書かないように。`store/naming.ts` の `enterNaming`）
  - 履歴: 書き終えた録音は `openHistory`、途中の録音は `startJob(path)`（続きから）。元ファイルが無ければ（`sourceAvailable: false`）行の ▶ を押せなくし、結果の画面に帯と「ファイルを選び直す」（`relinkSource`）
  - 「詳細をコピー」はブラウザのクリップボード（`navigator.clipboard.writeText`、使えなければ選択してコピー）
  - ドラッグ中の枠の色: アプリの中では `onFileDragOver` の位置が枠 `[data-drop-zone]` の中かで変える（`store/file.ts`）。見本（ブラウザ）は HTML5 のドラッグ

## 画面の言語（2026-09-27）

- 画面の文字は `src/i18n/ja.ts`（正）と `src/i18n/en.ts`（同じ形）に置く。部品は `useT()`、画面の外（store・lib）は `getT()` で今の言語の辞書を読む。
  英語の辞書に抜けや形の違いがあると型チェックで止まる
- 初めの言語は、前に選んだ言語 → この PC の言語（先頭が日本語なら日本語、それ以外は英語）。工程バーの右端の切り替えで変えられ、選んだ言語を覚える（`localStorage` の `kikiwake.locale`）。
  `<html lang>` も合わせる。テスト（window が無い所）では日本語
- 起動したときと切り替えたときに、今の言語をエンジンに知らせる（約束 版7 の `setLocale`。`store/bootstrap.ts` の `watchLocale`）。
  エンジンはこれで Mac のメニュー・既定の保存先の名前（英語では「〈元の名前〉_transcript」）・保存するファイルの中の言葉を合わせる（2026-09-27 に足した）
- エンジンが日本語で返す文は、画面が種類の目印で今の言語にする（辞書の `engine`）: エラー（`code`。`disk_full` は文から数を読む）、動作条件（文そのもの）、
  モデル名（`id`）、GPU の名前の「（10コア）」、「話者A」「不明」、手がかりの種類（「自己紹介」「呼びかけ直後」）、繰り返しの知らせ（時刻から作り直す）、段階の名前。知らない文はそのまま出す
- 英語の画面だけ、ファイルの画面に「今は日本語の録音だけ文字起こしできる」と一言出す（日本語の辞書では空）
- 言語を足すとき: `ja.ts` と同じ形の辞書を `src/i18n/` に足し、`index.ts` の `Locale`・`LOCALES`・`MESSAGES` に並べる。切り替えは自動で増える
- 日本語の見た目は、辞書へ移す前と後で、見本の 28 の作例の全要素（文字・位置・大きさ・文字の大きさと太さ）が同じことを測って確かめた（処理中の画面は数字を除いて）
- 書き起こし自体は今は日本語だけ（whisper の `-l ja`。英語の録音は今回やらない、と 2026-09-27 に決定）。開発用の切替パネルと見本だけの知らせは日本語のまま

## 履歴と閉じたときの状態（2026-09-27）

- 入口はファイルの画面の右上の「履歴」（録音を選ぶ前だけ出す。決定: 選んだあとはそのファイルの作業をするため）。工程バーでは「1 ファイル」の中
- 一覧は最後に使った順（エンジンが並べる）。1件ごとに名前・長さ・話者の数・名前あり・処理した日・保存した場所、状態の一言（途中・元のファイルが見つかりません・保存していない手直しあり）。
  ボタンは「開く」（書き終えた）か「続きから」（途中。元ファイルが無ければ押せない）と「消す」（確かめる画面つき。1件ずつ）
- 閉じたときの状態（`lib/draft.ts` の形）: 画面（名前付け・結果。完了の画面は結果）・入れかけの名前・行ごとの名前・確定・直した文字の履歴・表示しない人・保存の形式と保存先・最後に保存したときの手直しと保存したファイル・ファイルに保存していない手直しがあるか
- 次に起動したときはファイルの画面から（閉じた録音は履歴の一番上。決定）
- 見た目は完了の画面・ファイルの画面のカードと同じ部品（文字の大きさ・太さ・色・左端の位置を実測で突き合わせた）。英語でも 900×560 ではみ出さない

## 残っていること

- 見た目の細かい直しをするときは、ブラウザ（見本）とアプリの中（`../scripts/e2e_mac.sh synth` が画面の画像と要素の位置を残す）の両方で測る

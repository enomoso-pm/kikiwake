# Kikiwake の画面（ui/）

Kikiwake（聞き分け）の画面。React 18＋TypeScript＋Vite。
受け渡しの約束の正は `../contract/`（版6）。本物のエンジンとのつなぎ `src/api/tauri.ts` は、エンジン側（`../src-tauri/`）と組で直す。
画面の設計（UI 画面仕様書 ver1.1・動く見本）は公開していない。下の「仕様書に無くて決めたこと・仕様書と違う所」は、その仕様書と違う所の一覧。

## 状況

- 5画面（準備 → ファイル → 処理中 → 名前付け → 結果・保存）と完了の画面が、見本データでも本物のエンジンでも通しで動く
- 見た目は設計の見本と実測で突き合わせ済み（画面1〜5の主な部品の文字・余白・色・枠・列の幅・位置。見本のタイトルバーの分を引いて 1px 以内）
- 自動テスト（`npm test`）・型チェック・ビルドが通る
- 確かめた作例は下の「開発用の切替」の全部。4時間・1,468行（確認用60件）で、描く行は常に20行ほど、検索・次へ・スクロール・絞り込みは1回1〜2コマ
- アプリの中（Safari と同じ WebKit）では、`../scripts/e2e_mac.sh` が開発用のビルドだけに入る操作役で5画面を自動で通す（ボタンを押して読む。ui/ のファイルは使わない）

## 動かし方

```bash
npm install
npm run dev        # http://localhost:1430 （ポートは固定）
npm test           # 計算の部分の自動テスト（vitest）
npm run typecheck  # 型チェック（../contract も含む）
npm run build      # 型チェック＋ビルド。出力は ui/dist
```

ブラウザで開くと見本（`src/api/mock.ts`）で動く。右上の「開発用」から作例を切り替えられる:
画面 1〜5 へ直接／データ量（見本 2分44秒・4ラベル／多い 4時間・10ラベル・確認用60）／OS（Mac・Windows）／
準備（通常・注意あり・進めない・取得途中・取得失敗・取得済み）／ファイル（通常・非対応・前回あり）／処理（通常・途中で失敗、60倍・600倍）／
閉じる操作をまねる／名前付け（通常・注意あり、台本どおりの名前・同じ名前でまとめる・空にする、確定の失敗）／
結果（確認用1件・定番の誤認識・確認用なし・繰り返しあり）／保存（通常・同じ名前のファイルあり・失敗）。
ファイルは「ファイルを選ぶ」でも、何かのファイルを窓にドラッグしてもよい（拡張子で対応・非対応が変わる）。

見本だけの違い: 名前付けのサンプルと手がかりの「▶」は、声ではなく仮の音が鳴る（`../contract/README.md`）。
結果の画面の行の再生は、見本に録音全体が無いので無音で長さぶん進む。「Finder で表示」「アプリを閉じる」は、見本では右下や全体に「（見本）…」と出るだけ。

## エンジンとの受け渡しの細かい所

- Tauri は `npm run build` の `dist` を使い、`tauri dev` のときは開発サーバ（1430 番）を読む
- 製品のビルド（`npm run build`）には、見本・見本データ・開発用パネルは入らない。インラインの script・eval・外部の読み込みも無い
- 注意: 開発サーバ（`npm run dev`）は React の再読み込みのためにインラインの script を1つ入れる。`tauri dev` でも CSP の違反は出ていない
- 呼び方の約束:
  - `applyNames` には名前の入ったラベルだけを渡す。同じ人にまとめた名前（全角・半角の違いは同じとみなす）は、一覧で上のラベルの書き方にそろえて渡す
  - `saveOutputs` の `edits`: `names` はラベルの名前と違う行だけ（確認用の行は、確定していなくても名前があれば入れる）、`confirmed` は確定した確認用の行、`texts` は直した最後の文字。何も無ければ `edits` を付けない
  - 同じ名前のファイル（`SaveResult.existing`）が返ったら確認のダイアログを出し、「上書きする」で `overwrite: true` を付けて呼び直す
  - `revealInFileManager` には保存した最初のファイルのパスを渡す（まだ保存していなければ保存先）。`pickFolder` には今の保存先を渡す
  - `recordingSrc` は行の ▶ を押したときに呼ぶ。`audioSrc` はサンプルと確認用の手がかりの再生で呼ぶ
  - `onCloseRequested` が来たら、処理中なら「閉じる確認」、保存していない手直しがあればその確認を出し、「閉じる」で `closeApp()`。
    どちらでもなければ、確かめずにすぐ `closeApp()` を呼ぶ。エンジンは処理中か `setUnsavedChanges(true)` の間だけ知らせる（`store/bootstrap.ts` の `watchUnsavedEdits`）
  - 「詳細をコピー」はブラウザのクリップボード（`navigator.clipboard.writeText`、使えなければ選択してコピー）
  - ドラッグ中の枠の色: アプリの中では `onFileDragOver` の位置が枠 `[data-drop-zone]` の中かで変える（`store/file.ts`）。見本（ブラウザ）は HTML5 のドラッグ

## 仕様書に無くて決めたこと・仕様書と違う所

| 所 | 決めたこと | 理由 |
|---|---|---|
| 名前付け | 「話者を決められなかった部分の名前の手がかり」を話者カードの下にいつも出す（「田中 を話者C に入れる」ボタン付き） | 約束 版2 |
| 名前付け | 名前のまとめは全角と半角の違いを同じとみなす（仕様書 §13 Q4） | 決定（2026-09-26） |
| 名前付け | サンプルが無いラベル（発言がとても短い）は「聞けるサンプルがありません」 | 空の欄だと分かりにくいため |
| 名前付け | 10ラベル以上の下の帯は「10個のラベル」（9つまでは「5つのラベル」） | 「10つ」とは言わないため |
| 結果 | 書き起こしの繰り返しの注意の帯（約束 版4）は、表示する人の段の下・本文のすぐ上。押すとその時刻の行へ移って光る | 約束 版4 |
| 結果 | 同じ名前のファイルの上書きの確認（題「同じ名前のファイルがあります」、やめる／上書きする） | 約束 版3「いつも確かめる」。形は仕様書 §2.5 と同じ |
| 結果 | 保存するファイル名は `transcript_named.md` など（移植元の Python 版と同じ）。保存先の既定はエンジンが返す場所 | 約束 版3（仕様書 §8.9 の名前は使わない） |
| 結果 | 発言時間の数え直しは、`talkTime` を基に、行ごとの名前と「確定した」確認用の行を足し引きする（確定していない確認用の行は数えない） | 保存するファイルでは確定していない行は確認用の欄に残るため |
| 全体 | 時刻は `contract/format.ts` の書き方（1時間未満は「00:12」） | 保存するファイルと同じ規則 |
| 全体 | 日本語の文字だけヒラギノ角ゴシックで描く（`styles/app.css` の `@font-face "Kikiwake JA"`。この PC のヒラギノを `local()` で、日本語の範囲だけ。書体の指定の先頭） | アプリの中（Safari と同じ WebKit）では仕様書 §3.2 の `-apple-system` が日本語まで Mac の画面用の書体で描き、ブラウザで確かめた見た目より約 8% 細身で行も低くなる（18px で幅 180→166px・高さ 27→21px）。ブラウザでの見た目に合わせた（2026-09-26 決定）。残る差（折り返し位置、英数字だけの文字や入力欄の高さが数 px）は描き方の違いで消せない |
| 全体 | 所要時間の目安は分に四捨五入（2分44秒の録音で「約 1 分」）。録音の長さは「2:43」「1:07:48」 | 仕様書に書かれていないため |
| 全体 | 動作条件が読めなかったときは、準備の画面の題の下にエラーの帯 | 仕様書に書かれていないため |
| 全体 | 2回目以降の起動は、AI モデルがそろい動作条件に error が無ければファイル選択から（仕様書 §13 Q1 の仮の扱いのまま） | 仕様書の仮の扱い |
| 全体 | 保存していない手直し（行の名前・確認用の確定・文字）があるまま閉じようとしたら「保存していない手直しがあります。閉じますか？」（やめる／閉じる）。保存したあとに直したときも同じ。保存した状態に戻せば確かめない | 決定（2026-09-26）。アプリでは約束 版6 の `setUnsavedChanges` で届く |
| 全体 | 一度も保存していない結果（手直しは無い）のまま閉じる・別の録音へ移るときは確かめない | 決定（2026-09-26）。同じ録音を選び直せば、書き起こしをやり直さずに数秒で戻れるため（約束 版6） |
| ファイル | 前回の書き起こしまでそろっている録音（`previous.resultReusable`）は「前回の結果を使います」（書き起こしをやり直さずに、すぐに名前付けへ）、所要時間の目安は「すぐに終わります」 | 約束 版6。仕様書に無い |
| ファイル | アプリの中では、ドラッグ中の枠の色を `onFileDragOver` の位置で変える（HTML5 の知らせは届かない）。見本（ブラウザ）は今までどおり HTML5 | 約束 版6 |
| 名前付け | この録音で前に確定した名前（`JobDone.names`）を、最初から入れておく | 約束 版6 |
| 工程バー | 4項目（1 ファイル・2 処理・3 名前付け・4 結果）。準備は工程に入れず、準備の画面では4つとも「まだ」の見た目で並べる（「次へ」で「1 ファイル」から工程に入る）。完了の画面では4つとも「済んだ」の見た目。色や部品は仕様書 §2.2 のまま | 決定（2026-09-26。準備は一度やれば終わりのため）。仕様書は「1 準備」〜「5 結果」の5項目 |
| 結果 | 右上（「詳細」の隣）に「完了」を常に置く。保存したかどうかに関係なく押せる。右下の「保存」は保存したあとも「保存」のまま | 決定（2026-09-26。保存しないと終われない形にしないため。保存すると右下が「完了」に変わる形は試して取りやめ） |
| 完了（新しい画面・工程の外） | 「← 文字起こしに戻る」・題・カード（録音の名前・保存したファイル・保存先・「Finder で表示」）・「別の録音を文字起こしする」「Kikiwake を終了」。保存していなければ題は「文字起こしを終えました」で「まだ保存していません（選び直せばすぐ戻れる）」の帯、保存していない手直しがあれば注意の帯。手直しが残っていれば「別の録音」「終了」で今までの確認を出す。部品はファイルの画面のカード・帯と同じ形 | 決定（2026-09-26）。仕様書に無い |
| 工程バー | 結果を一度出したあと、名前付け・結果の画面から「1 ファイル」も押せる（ツールチップ「別の録音を選ぶ」）。保存していない手直しがあれば「保存していない手直しがあります」（やめる／別の録音へ移る）で確かめる。移ると今の文字起こしの状態は消える | 決定（2026-09-26）。仕様書は 1〜3 を押せない |

- 見た目の細かい直しをするときは、ブラウザ（見本）とアプリの中（`../scripts/e2e_mac.sh synth` が画面の画像と要素の位置を残す）の両方で測る
